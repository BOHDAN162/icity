# iCITY 113Н — дизайн-система, вариант D: «Фритта»

Светлая. Красного много. Палитра от фасада, не от интерьера.

---

## 0. Идея

Фриттованное стекло — это керамические точки, напечатанные по стеклу.
Плотность точек меняется: у кромки густо, к центру разрежённо. Именно так
сделаны красные срезанные углы башни — не сплошная заливка, а растр.

**Растр из красных точек — единственный декоративный элемент сайта.**
Он не орнамент: плотность точек означает интенсивность. Густо там, где
важно; разрежённо там, где фон.

Это отвечает на два требования сразу. Красного на странице много и он
заметен — но он не давит, потому что это не плашки, а растр. И он взят
у объекта, а не подобран.

---

## 1. Палитра

Источник — фасад: алюминиевые импосты, перфорированные панели, холодное
стекло, красная фритта. Интерьерные рендеры в подборе не участвовали.

```
--white      #FFFFFF
--paper      #F2F4F5   фон страницы, холодный светлый
--paper-2    #E6EAEC   подложка секций
--paper-3    #DDE2E5   ступень ниже: подложка колонки «отделка с нуля» (§6 copy.md)
--alu        #B7BFC4   алюминий: линии, импосты, рамки
--ink        #101619   графит, весь текст и заголовки
--ink-60     #566065   вторичный текст (контраст 5,6:1)

--frit       #ED1C29   чистый iCITY. Только растр и линии 1–2 px
--frit-deep  #C4141C   заливки и текст (белый на нём — 6,1:1)
```

**Почему два красных.** Белый текст на чистом `#ED1C29` даёт 4,4:1 —
ниже порога AA для основного кегля. Поэтому все заливки, кнопки и
красный текст идут на `--frit-deep`, а чистая фритта живёт в точках
и волосяных линиях, где контраст не нормируется.

### Растр

```css
--frit-dense:  radial-gradient(circle, #ED1C29 1.4px, transparent 1.5px) 0 0/8px 8px;
--frit-mid:    radial-gradient(circle, #ED1C29 1.1px, transparent 1.2px) 0 0/12px 12px;
--frit-sparse: radial-gradient(circle, #ED1C29 0.9px, transparent 1px)   0 0/18px 18px;
```

Три плотности и ни одной между. Растр появляется: полосой на стыке секций,
подложкой под крупными числами, заливкой активной зоны на плане,
полосой под ключевым числом. Больше нигде.

На мобильном — только `--frit-mid`, мелкий растр на плотных экранах
муарит и жрёт время отрисовки.

## 2. Типографика

Три гарнитуры, роли разведены жёстко. **Literata** — заголовочные уровни
и первый экран. **Golos Text** — весь остальной текст и интерфейс.
**JetBrains Mono** — числа, метрики и микро-лейблы. Смешивать роли
нельзя: это и есть система.

Все три вариативные, все под OFL 1.1, у всех кириллица нарисована
профильными типографами, а не автоконвертирована из латиницы:

- **Literata** — кириллица Веры Евстафьевой (консультант Кирилл Златков,
  ассистент Елена Новосёлова), золото Modern Cyrillic 2021; латиница
  Вероники Буриан и Хосе Скальоне, TypeTogether. Заказана Google
  для Play Books — то есть нарисована под долгое чтение с экрана.
- **Golos Text** — Александра Королькова и Виталий Кузьмин, Paratype,
  2019. Рисовалась под государственные и сервисные сайты: нейтральный
  гротеск, который не спорит с содержанием.
- **JetBrains Mono** — моноширинная, табличные цифры по умолчанию,
  ноль разницы между `tabular-nums` и пропорциональными.

Ставятся через `next/font/google`, самохост, **ноль внешних запросов** —
для российских сетей это не мелочь, а страховка. Сабсеты ровно два:
кириллица и латиница. Вес не указан ни у одной — Next отдаёт вариативный
файл с полной осью.

```js
import { Literata, Golos_Text, JetBrains_Mono } from 'next/font/google';

const literata = Literata({
  subsets: ['cyrillic', 'latin'],
  axes: ['opsz'],          // без этого оптическая ось не приедет вовсе
  display: 'swap',
  variable: '--font-literata',
});
```

**`axes: ['opsz']` — не украшение.** Без явного перечисления Next
скачивает файл с одной осью `wght`, и объявленное в `tokens.css`
`font-optical-sizing: auto` становится мёртвой строкой: исполнять его
браузеру нечем. Замер: строка на 40 px при `opsz 7` занимает 417,78 px
против 374,57 px при `opsz 72` — ось живая, разброс 11,5 %. Контроль
на Golos, у которого оси нет: 359,20 px в обоих случаях.

Отсюда же следствие, на котором легко обжечься: **ширина глифа Literata
кеглю не пропорциональна**. Мерить только на живом элементе в настоящем
кегле — пересчёт с пробного врёт на 13 %.

Диапазоны осей: Literata **200–900**, Golos Text **400–900**,
JetBrains Mono **100–800**. У Golos всё ниже 400 схлопывается в 400
молча — замер даёт одну и ту же ширину строки на 300, 350 и 400.
Промежуточные значения внутри диапазона (450, 550, 650) работают.

Курсива в системе нет, и теперь это ограничение держим сами: у всех
трёх вариативных гарнитур курсив физически есть, а прежний static-инстанс
EB Garamond его просто не отдавал.

| Роль | Гарнитура | Размер | Интерлиньяж | Трекинг |
|---|---|---|---|---|
| `display-xl` | **Serif 600** | `clamp(40px, 6.4vw, 86px)` | 1.00 | −0.025em |
| `display-l` | **Serif 600** | `clamp(30px, 3.6vw, 50px)` | 1.06 | −0.022em |
| `display-m` | **Serif 400** | `clamp(30px, 3.6vw, 50px)` | 1.06 | −0.012em |
| `heading` | Sans 600 | `clamp(20px, 1.6vw, 25px)` | 1.26 | −0.012em |
| `lead` | Sans 400 | `clamp(18px, 1.35vw, 21px)` | 1.52 | 0 |
| `body` | Sans 400 | 17px | 1.60 | 0 |
| `small` | Sans 400 | 15px | 1.52 | 0 |
| `num-xl` | **Mono 500** | `clamp(42px, 5.0vw, 70px)` | 1.0 | −0.020em |
| `num-m` | **Mono 500** | `clamp(26px, 2.4vw, 34px)` | 1.0 | −0.020em |
| `label` | **Mono 500** | 12px | 1.0 | +0.16em, uppercase |
| `hero-title` | **Serif 400** | `clamp(20px, 6.4vw, 34px)` ↑767, иначе `clamp(30px, min(4.9vw, 11svh), 64px)` | 1.24 / 1.18 | +0.11em / +0.16em, uppercase |
| `hero-mark` | **Serif 400** | `clamp(11px, 0.95vw, 14px)` | 2.0 | +0.20em / +0.24em |

Граница между антиквой и гротеском проходит по `heading`: на 20–25 px
антиква начинает спорить с текстом под собой, поэтому третий уровень
остаётся на Golos. Вес там 600, а не 500: Golos 500 оптически легче,
чем был Geist 500.

`display-m` — **не «`display-l` поменьше»**: кегль и интерлиньяж
у них одинаковые, различаются только вес и трекинг. Ступень заведена
1 сентября 2026 под единственное место на сайте, где антиква стоит
**поверх фотографии**, а не на `--paper`, — подпись кадра вида
(«Панорама», `OfficeStop`). На белой вуали поверх снимка полужирный
600 весит больше метрик рядом, ради которых экран и сделан,
а −0.022em слепляет «нр» и «ор»: минус такого порядка рисовался под
плотный набор, широкие овалы Literata его не терпят. Трекинг −0.012em
здесь пара к весу 400 — тонкому штриху нужен воздух, которого
полужирному не нужно; совпадение с `tr-head` не случайно (оба стоят
там, где кириллица набрана нежирно), но токен отдельный, чтобы правка
заголовков не ездила на подпись кадра и наоборот.

Масштаб сохранён нарочно. Ступень вниз (400 / 40 px / −0.006em)
рисовалась и была отклонена после живого просмотра: подписи надо было
снять **вес, а не размер**. Ширина слова на 1440 — 248,5 px против
252 прежних.

Интерлиньяж 1.06 не менять: им коробка строки сходится с коробкой
`num-m`, иначе точечные подчерки на ховере встают не в одну линию.
Замер разницы низа коробок на живой странице: **0,0 px** на 1440,
0,3 px на 1000. Вес на метрики строки не влияет, поэтому смена
600 → 400 их не сдвинула — сдвинул бы кегль.

Контраст правкой не затронут, и это ожидаемо: WCAG считает по цвету,
а цвет, кегль и позиция глифов те же. Замер маской глифов по реальным
пикселям кадра — **5,85 на 1440 и 5,68 на 1000, до и после одинаково**.

### Трекинг — функция кегля и регистра

Прежние значения (−0.045 / −0.035 / −0.02 / −0.01 / −0.04) были поправкой
под плотный набор Geist. Кириллица шире латиницы по природе и латинского
минуса не терпит: на Golos и Literata эти значения слепляют буквы.
Правило теперь одно:

- крупный кегль — отрицательный трекинг, **потолок системы −0.025em**;
- текст — **ноль**;
- прописные — **всегда положительный**, 0.16em.

`--tr-label` поднят с 0.10 до 0.16em: прописная кириллица без разрядки
читается как аббревиатура, а JetBrains Mono шире Geist Mono.
Самое узкое место этого значения — `.mode` в `Location.module.css`
(`flex: 0 0 62px`, mono 10px прописными): «ПЕШКОМ» занимает ровно 62 px
из 62 доступных. Поднимаешь `--tr-label` — перемеряй эту строку первой.

### Табличные цифры — точечно, не глобально

`font-variant-numeric: tabular-nums` объявлен на `.num-xl` и `.num-m`,
а не на `body`. У Golos табличная цифра на 4 % шире пропорциональной
(«0123456789» на 17 px — 102,77 против 98,77 px), и в связном абзаце
«244,1 м²» от неё разреживается. На `--mono` свойство не меняет ничего:
JetBrains Mono моноширинная, замер даёт ровно 0 разницы, — оставлено
как объявление правила и страховка на случай смены гарнитуры.

### Первый экран

Заголовок и знак-столбик набраны Literata — тем же `--serif`, что
и заголовочные уровни. Прежде здесь жила отдельная гарнитура
(EB Garamond) как снятый заказчиком запрет на вторую; теперь антиква
в системе своя, и первый экран перестал быть исключением.

Трекинг у обеих ролей **положительный**, в отличие от заголовочных
уровней: минус там — поправка под крупный кегль, а прописные от минуса
слипаются. Прописные вразрядку — и есть приём первого экрана.

Кегль ограничен двумя потолками сразу. **По ширине**: «ДЕЛОВОЙ МОСКВЫ» —
14 прописных с трекингом, самая длинная строка макета, и она обязана
оставаться одной строкой вплоть до 320 px. Замер под Literata при
трекинге 0.11em, доступно 280 px:

| Кегль | Размер на 320 px | Строка | Итог |
|---|---|---|---|
| 7.8vw (под Garamond) | 24,96 px | — | перенос, четыре строки |
| 6.6vw | 21,12 px | — | перенос, четыре строки |
| 6.5vw | 20,80 px | 275,1 px | запас 4,9 px — мало |
| **6.4vw** | **20,48 px** | **270,9 px** | **запас 9,1 px** |

**По высоте**: строк три, и `11svh` держит блок под 39 % экрана —
на низком окне 1440×620 замер даёт 36,5 %, кнопка «Войти» целиком
в кадре. **Поднимаешь кегль или трекинг — перемеряй на 320 px.**

## 3. Сетка и ритм

Контейнер 1440, поля 64 / 40 / 20, 12 колонок, гаттер 24 / 20 / 16.
Рельса нет — вместо него работают полосы растра на стыках секций,
высотой 48 px во всю ширину, плотность `--frit-sparse`.

Отступы секций: 120 / 92 / 68. Ритм: `4 8 12 16 24 32 48 64 96 120 168`.

Радиусы **2 px** на кнопках и полях, 0 везде остальном. Два пикселя,
а не четыре: набор внутри кнопки плотный, при радиусе 4 коробка
выглядит мягче своего содержимого.

Тени отсутствуют.

## 4. Компоненты

**Кнопка основная.** Заливка `--frit-deep`, текст белый Sans 500 17px,
высота 54, радиус 2. Hover — `#A81016`. Focus — обводка 2 px `--ink`.

**Кнопка вторичная.** Рамка 1 px `--alu`, текст `--ink`.
Hover — рамка `--ink`, фон `--white`.

**Поле ввода.** Фон `--white`, рамка 1 px `--alu`, высота 54, радиус 2.
Focus — рамка `--frit-deep` 1 px и внешняя обводка 2 px `rgba(237,28,41,.18)`.

**Липкая панель.** Высота 64, фон `--paper` сплошной, сверху линия 1 px `--alu`.
Растра на панели нет. Она висит через весь сайт, и растр на ней превращается
в фоновую текстуру — приём обесценивается там, где работает по смыслу.
Список мест для растра — §1, и панели в нём нет.
Блюра тоже нет: `--paper` непрозрачный, размывать под ним нечего.
Кнопка внутри панели — высота 44, единственное место, где кнопка ниже 54.

**Ряд чисел.** Mono, разделены вертикальными линиями `--alu` 1 px.
Под четвёртым числом («0 капзатрат») — подложка `--frit-dense`
высотой 6 px, единственное место, где растр стоит под текстом.

**Вуаль.** Единственное разрешённое отступление от запрета на градиенты
вне слоя неба. Это **служебный приём, а не декор**: рендеры зон светлые,
тёмный текст на них не держит 4,5:1, а плашка под каждым блоком превращает
экран в стопку белых прямоугольников поверх фотографии.

Вуаль — градиент от кромки кадра в прозрачность, `--paper` с переменной
альфой, без единой резкой границы. Текст лежит прямо на кадре; вуаль
отвечает только за коэффициент контраста.

Условия, при которых приём остаётся приёмом, а не расползается:

1. Вуаль растёт **от кромки экрана**, не появляется пятном посередине.
2. Цвет только `--paper`, меняется исключительно альфа. Никаких других
   цветов, никаких цветных градиентов.
3. Ставится там, где на кадре лежит текст, и по высоте не больше, чем
   нужно этому тексту.
4. Контраст проверяется **по реальным пикселям кадра под текстом**, а не
   по предполагаемому фону. Не хватает — углубляется альфа вуали,
   а не возвращается плашка.
5. За пределами кадров зон вуаль не применяется. На обычных секциях фон
   сплошной, и приём там не нужен.

Тени по-прежнему запрещены: вуаль их не заменяет и не имитирует.

**Кнопка перехода.** Круг 56 px, рамка 1 px `--alu`, фон `--paper`,
внутри только стрелка, повёрнутая по азимуту зоны на плане. Имени на
кнопке нет: оно появляется подписью над кругом по наведению и по фокусу,
а для скринридера стоит `aria-label` — всегда, независимо от того, видна
подпись или нет. Круг — единственное место в системе с радиусом, отличным
от 2 px и 0: форма задана самим элементом.
Стрелка возврата тише прямых: `--ink-60` вместо `--ink`, на наведении
подтягивается. На мобильном круг 52 px.

**Возврат к башне.** Не ровня целевой кнопке и не должен на неё походить:
текст `--ink-60` со стрелкой, без плашки и без рамки, на наведении `--ink`.

**Мелкий шрифт.** Юридически обязательные строки набираются `--small`
цветом `--ink-60` и не получают собственной поверхности. Они не первое,
что читают.

**План поверх всего.** Фон `--paper`, шапка с линией `--alu` снизу,
поле просмотра на `--paper-2`. Зум ступенями по 50 %, от 100 % до 400 %.
Закрывается по Esc и по клику вне листа.

**План 244 м².** Стены `--ink` 1,5 px, мебель `--alu` 0,5 px.
Зоны без заливок; активная зона заливается `--frit-mid`.
Никаких цветных зон — цвет на плане ровно один.

## 5. Движение

Быстрое. Набор здесь не декоративный, и движение под него — тоже:
никаких доездов и пружин.

```
--ease-out  cubic-bezier(0.16, 1, 0.30, 1)
--t-micro   140ms
--t-reveal  380ms
--t-scene   620ms
```

Появление: `opacity` плюс `translateY(12px)`, 380 мс, стаггер 100 мс
(`--stagger` в `tokens.css`), максимум четыре элемента.

### Проявление первого экрана — единственное медленное место

`opacity` 0→1, **1900 мс, `linear`**, задержка 200 мс, стаггер 160 мс.
Единственное место системы с таким темпом и единственное без `translateY`.

**Заголовок проявляется побуквенно и вразнобой** — не строкой и не
блоком. У каждой буквы своя задержка: детерминированный хеш от номера
буквы, растянутый на `--hero-in-scatter` (560 мс). В референсе замерено
~370 мс разброса между серединами проявления при длительности буквы
~1,8 с; у нас чуть шире, чтобы вразнобой читался на беглом взгляде,
а не только в покадровом замере.

На уменьшенных кадрах этот разброс усредняется и выглядит как одно
общее проявление — так его один раз уже и проглядели. Проверять только
в нативном разрешении или замером непрозрачности каждой буквы.

**Абзац выезжает снизу из-под маски**, строка за строкой: 1600 мс,
`--ease-standard`, шаг между строками 160 мс. Единственное место первого
экрана, где движется не только непрозрачность, и единственное, где
уместна кривая: у движения есть конечная точка, строка должна подъехать
и мягко встать. Непрозрачности здесь нет — маска и так открывает строку
постепенно, а фейд поверх сделал бы край мутным вместо чёткого.

**Заголовок и абзац стартуют ВМЕСТЕ**, на 360 мс: одна ступень, а не две.
Прежде абзац ждал ещё и весь разброс букв (+880 мс) и приходил, когда
заголовок был уже дочитан — первый экран собирался в три приёма. Темп
каждого при этом прежний: буквы 1900 мс, строки 1600 мс, и пересечение
здесь и есть смысл. Кнопка и выбор звука остаются ступенью ниже, 1240 мс —
им положено прийти последними. Замер: буквы 366–890 мс, строки 360 и
520 мс.

**Прогон подчёркивания** под «Войти без звука»: 520 мс,
`--ease-standard`. Линия уходит вправо, точка опоры перекидывается влево
на нулевой ширине, линия приходит слева. Вдвое дольше обычного ховера
(`--motion-base` 250 мс), потому что движений два подряд.

Почему не существующие токены. `--t-reveal` (380 мс) — это микро-появление,
здесь нужен киноплан около двух секунд. А `--ease-out` / `--ease-soft`
на 1900 мс отдают половину непрозрачности за первые ~190 мс и 94 % к
760-й — «медленное проявление» кончилось бы за первую треть. Поэтому
ramp линейный: это отсутствие кривой, а не четвёртая кривая в словаре.
Стаггер 160, а не 100: 100 мс — это 5 % от 1900, шаг неразличим.

`translateY` тут вреден: сдвиг, растянутый на 1900 мс, превращается
в медленное всплытие и спорит с полётом камеры, который начнётся следом.

Запускается **не с монтирования, а по сигналу занавеса** (`lib/curtain.ts`) —
прелоадер держит экран закрытым первые ~2,1 с. Подробности и грабли —
в `AGENTS.md`, раздел «Hero-видео».

Растровые полосы на стыках секций проявляются сдвигом плотности:
`--frit-sparse` → `--frit-mid` за 620 мс при входе секции в вьюпорт.
Реализовать сменой `background-size`, не перерисовкой.

Жест удержания остался только на экране с окном: 120 мс захват,
5,0 с полный проход, 900 мс торможение, автостарт 3,0 с.
На первом экране жеста нет — там одна кнопка входа, а скролл
заблокирован на всё время жизни hero.

Смена зоны в офисе — перекрёстное растворение за `--t-scene`,
без сдвигов. Возврата из офиса к башне нет: кнопка «К башне» удалена
вместе с секвенцией, стадия ходит только вперёд, к первому экрану
возвращает исключительно перезагрузка (см. `AGENTS.md`).

### Ховер весом — один приём на два места

Числа тяжелеют под курсором с **500 до 650 за 180 мс
`--ease-standard`**: ряд «Помещение 113Н» на Landing и полоса фактов
в «Экономике сделки». Число 180, а не `--motion-base` 250, — из
Landing, откуда приём и взят; расходиться этим двум местам нельзя.
Только точная мышь, `(hover: hover) and (pointer: fine)`.

Вес объявляется **дважды** — в шорткате `font` и отдельной строкой
`font-variation-settings: 'wght' 500`. Это не дубль: анимируется ось
`wght`, а интерполировать её не из чего, пока база не названа явно —
из `normal` вес прыгает скачком.

Раскладку это не двигает: JetBrains Mono моноширинный, ширина знака
от веса не зависит. Замер полосы фактов на 1440 — коробки всех трёх
ячеек и обеих строк в них совпадают до 0,00 px в покое и на ховере.
Призрачный дубль на весе 700 у `.num` в Landing стоит не ради ховера,
а чтобы держать ширину, пока число считается от нуля.

Точечный подчерк идёт вместе с весом только там, где числа читают
поодиночке, — на Landing и на кадре вида. В полосе фактов его нет
нарочно: там на курсор отвечает ячейка целиком, и красная полоса под
каждой строкой превратила бы спокойную полосу фактов в подсвеченную
таблицу.

**В полосе фактов ячейка отвечает набором, и только набором**: обе
строки тяжелеют 500 → 700 и расходятся по трекингу — подпись
на середину между `--tr-label` и `--tr-mark` (0.20em, ступень,
на которой `--tr-mark` стоит на телефоне), число с `--tr-num`
на `--tr-lead`, то есть отрицательный трекинг просто снимается.
Новых значений в шкале не заводится. Вес здесь тянет, разрядка
поддерживает: первая версия шла на 650 и полном `--tr-mark`,
и после живого просмотра заказчик попросил букв жирнее, а разъезда
вдвое меньше. Серая подложка под
ячейкой тут была полдня 1 сентября 2026 и снята заказчиком в тот же
день: заливка читалась как рамка, а не как отклик. Ни фона, ни цвета,
ни подчерка. Раскладка не двигается — строки набраны от левого края
ячейки, разъезжается только их собственная ширина: замер на 1440,
коробки ячеек 437,33 × 95,70 и `dl` 1312 × 97,70 одинаковы в покое
и на ховере, самая длинная строка растёт с 264,5 до 273,6 px при
ширине ячейки 437.

## 6. Чем рискуем

Растр — приём с высокой ценой ошибки. При неверной плотности он
превращается в фактуру дешёвой полиграфии, а на ретине может муарить
при масштабировании. Обязательно проверить на реальном айфоне до того,
как разгонять по всем секциям: сначала одна полоса, потом остальные.

Второй риск: красного действительно много, и если арендатор не любит
красный — сайт будет читаться агрессивно. Смягчение — растр всегда
разрежённый, сплошных красных плашек нет нигде, кроме кнопки.

### Текст поверх кадра: мерить, а не прикидывать

Номинальные контрасты палитры взяты против `--paper` и над кадрами
не действуют. На постере облаков `--ink-60` не проходит нигде
(худший 1,55:1), а `--alu` не годится даже на границы (1,05–2,23:1
против порога 3:1). Поэтому первый экран несёт только `--ink`.

Замер — по реальным пикселям, а не на глаз. Прогонять после любой
пересборки постера; каждая ячейка, куда попадает текст, обязана быть
≥ 4,5. Сегодняшняя база: десктоп минимум **5,8**, мобильный **4,4**
(только левый верхний угол, туда стек не заходит).

```bash
ffmpeg -hide_banner -loglevel error -i public/video/poster/hero-desktop-2560.webp \
  -vf scale=360:-1 -pix_fmt rgb24 -f rawvideo - | node -e '
const c=[];process.stdin.on("data",d=>c.push(d)).on("end",()=>{
const b=Buffer.concat(c),W=360,H=b.length/3/W;
const li=v=>{v/=255;return v<=0.04045?v/12.92:Math.pow((v+0.055)/1.055,2.4)};
const L=(r,g,x)=>0.2126*li(r)+0.7152*li(g)+0.0722*li(x);
const cr=(a,z)=>(Math.max(a,z)+0.05)/(Math.min(a,z)+0.05);
const ink=L(0x10,0x16,0x19),R=10,C=6,m=Array.from({length:R},()=>Array(C).fill(1));
for(let y=0;y<H;y++)for(let x=0;x<W;x++){const i=(y*W+x)*3,l=L(b[i],b[i+1],b[i+2]);
const r=Math.min(R-1,y/H*R|0),q=Math.min(C-1,x/W*C|0);if(l<m[r][q])m[r][q]=l;}
m.forEach((r,i)=>console.log((i*10+"%").padStart(4),
  r.map(v=>cr(ink,v).toFixed(1).padStart(5)).join("")));});'
```

Вуаль под текстом эту задачу не решает: маска поверх полноэкранного
кадра перерисовывает его на каждом тике и роняет частоту на средних
телефонах (`AGENTS.md`).
