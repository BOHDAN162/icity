# iCITY 113Н — тексты

Все тексты сайта, по экранам. Числа — из `docs/facts.md`, ничего сверх него.

**Правила набора.** Разряды — узкий неразрывный пробел `U+202F`: `1 300 000 ₽`.
Десятичная запятая: `244,1 м²`, `3,8 м`. Тире — длинное, с пробелами.
Кавычки — «ёлочки». Микро-лейблы капителью, всё остальное строчными.

**Запрещённые слова.** «Премиальный», «уникальный», «не имеющий аналогов»,
«статусный», «элитный», «инновационный», «пространство мечты». Если хочется
написать прилагательное — напиши вместо него число или название.

## 0–1 · Герой: постер, «Войти», полёт

Экран открывается **внутри облаков**: постер — первый кадр ролика,
башни не видно вообще. Сверху копия, в центре одна кнопка. Клик —
ролик полёта играет один раз вперёд (9,8 с): проход сквозь облака,
из них выходит башня, ровный полёт на уровне 23 этажа, в финале камера
уходит вверх и снизу выезжает ресепшн. Скролла и подсказок про скролл
на этом экране нет; копия гаснет со стартом ролика.

**Знак-столбик** (бывший надзаголовок; три строки, сериф, вразрядку)
```
iCITY
SPACE TOWER
23 ЭТАЖ
```

Те же три факта, что стояли одной строкой, просто разложенные в столбик —
композиция первого экрана переработана по референсу. `text-transform`
здесь нет нарочно: он превратил бы бренд в «ICITY».

**Заголовок** (три строки, сериф, ЗАГЛАВНЫМИ вразрядку)
```
В самом
центре
деловой Москвы
```

> **Разошлось с утверждённым — и это решение заказчика, а не дрейф.**
> Прежний вариант «Офис, в который / въезжают завтра» нёс самую сильную
> опору документа — ноль срока — но из живой сборки он выпал давно
> и незаметно. Заказчик выбрал нынешнюю формулировку и трёхстрочную
> разбивку под композицию референса. Если ноль срока захочется вернуть,
> «Офис, в который / въезжают / завтра» ложится в ту же разметку.

В разметке текст остаётся строчным, заглавные делает CSS: скринридер
должен читать нормальную фразу, а не побуквенную аббревиатуру.

Линии-разделителя больше нет: в новой композиции её нет и в референсе,
а перед удалением она уже была обесцвечена в `--white` и на светлом
постере не читалась вовсе.

**Подзаголовок**
```
244,1 м² с отделкой от PRIDEX.
Место, где решения становятся масштабными.
```

> Заменён заказчиком 1 сентября 2026. Прежняя вторая строка — «Ноль
> капитальных затрат до въезда» — несла опору «ноль затрат»; новая
> работает на образ, а не на аргумент. Аргумент при этом уходит
> с первого экрана совсем: в заголовке его тоже нет. Если понадобится
> вернуть, строка ложится в ту же разметку без правок.
> «от PRIDEX», а не «PRIDEX» — тоже решение заказчика.

**Кнопка**
```
Войти
```

**Второй вход** — рядом с кнопкой, тем же жестом выбирается звук
```
Войти без звука
```

Без подсказок и счётчиков: ролик греется фоном с загрузки страницы,
к клику он в кэше. При `prefers-reduced-motion` тот же экран без видео,
«Войти» открывает офис мгновенно — отдельная строка про отключённую
анимацию не нужна.

Вся копия **проявляется медленно, за 1,9 с**, и стартует не с загрузки,
а по сигналу от прелоадера. Заголовок при этом проявляется **побуквенно
и вразнобой**, а не строкой. Тайминги и причина — `docs/design-system.md`
§5 и `AGENTS.md`, «Hero-видео».

**Экономических опор на первом экране больше нет ни одной.** Ни «нуля
срока» в заголовке, ни «нуля капзатрат» в подзаголовке: обе строки
заменены заказчиком на образные. Подзаголовок держит только площадь
и подрядчика по отделке — имя PRIDEX для арендатора класса А+ значит
больше, чем слово «дизайнерская». Аргументы теперь начинаются
с приземления (раздел 2), где стоит ряд чисел.

**Мебель в подзаголовке не упоминается.** Старая версия («отделка PRIDEX
и мебель уже внутри») факт-чек не проходит: `docs/facts.md` прямо
предупреждает — мебель в ставку не входит, есть только дизайн-проект
мебели, отделка PRIDEX выполнена. «С мебелью» — ошибка из презентации,
её нельзя повторять ни в каком варианте текста.

> Запасные варианты на случай возврата к «нулю срока» в заголовке:
> «Офис, в который / въезжают / завтра» — три строки, ложится в нынешнюю
> разметку без правок. Если «завтра» сочтут обещанием конкретного срока —
> «Офис, готовый к въезду. Не через полгода.» Ритм слабее, смысл тот же.

## 3 · Вид из окна

Полноэкранный кадр, который поднимается снизу, когда листаешь вниз из
любой зоны офиса. Ни жеста удержания, ни звука, ни переключателя времени
суток здесь нет — экран собран, а этого нет нигде в проекте. Управление
одно: прокрутка. Подпись проявляется на выдержке, когда кадр уже дошёл
доверху, и уходит вверх на шве. Устройство — `docs/office-flow.md`.

**Надзаголовка нет.**

**Заголовок**
```
Панорама
```

Заголовок за 1 сентября 2026 года менялся дважды. Сначала одно слово
«Вид» стало предложением «Панорама на десятки километров вокруг»,
к вечеру от предложения остался только первый его член. Хвост снят
заказчиком: кадр показывает эти десятки километров сам, и подписывать
их словами значит объяснять картинку, которая в объяснении не
нуждается. Тогда же ушёл надзаголовок «23 ЭТАЖ» — этаж стоит числом
справа, в ряду метрик, и дважды на одном экране он не нужен.

Заголовок и ряд чисел выровнены по общей базовой линии, а не по нижней
кромке блоков: слева одно слово антиквой, справа два числа моно
с подписями под ними.

**Ряд чисел справа**
```
23 ЭТАЖ     3,8 ПОТОЛКИ, М
```

**Alt кадра** — описывает кадр, а не предложение:
```
Вид из окна 23 этажа на Москва-Сити
```

Это кульминация и единственное, что нельзя получить, не приехав.
Поэтому текста здесь минимум: работает картинка.
Формулировку «исключительная особенность высотного проектирования»
из буклета MR Group не цитируем — это их маркетинг, а не наш факт.

**Сторон света на этом экране нет и не будет.** В `facts.md` они помечены
как гипотеза. У кадров-заглушек буквы румбов впечатаны в пиксели —
их снимает обрезка в `scripts/view-images.mjs`. По той же причине их нет
и в `alt` второго кадра, хотя описать его сторону было бы проще всего.

**У второго кадра подписи нет вовсе.** Решение заказчика от 3 сентября
2026: первый кадр уже назвал и панораму, и этаж, второй просто добавляет
обзора. Ни заголовка, ни метрики, ни вуали — вуаль здесь подложка
под текст, и без текста ей нечего держать. Захочется подписать —
это возврат к разговору, а не правка строки: два подписанных кадра
подряд читаются как список, а не как вид из окна.

> **Оба кадра сейчас заглушки.** Скриншоты стороннего панорамного
> просмотрщика, а не съёмка из помещения. Настоящие кадры приедут позже;
> что менять — списком в шапке `components/OfficeStop.tsx`.

> **Что снято по сравнению с прежней спецификацией.** Удержание
> «Держите, чтобы открыть окно», переключатель звука «Со звуком лучше»
> и переключатель «ДЕНЬ · ЗАКАТ». Ни звука, ни второго состояния панорамы
> в проекте нет, а жест на экране, где он ничего не открывает, — это
> обещание, которое сайт не выполняет. Строки сохранены здесь: если
> появится вторая панорама или запись ветра с 23 этажа, они вернутся
> вместе с ними, а не раньше.

## 4 · Офис

Остановка сразу после входа в стекло. Страница листается как обычно:
вниз из любой зоны поднимается кадр вида (раздел 3), вверх — возвращается
башня. Заменяет собой прежние отдельные экраны «План» и «Зоны».

**Обход зон** — в порядке, как ходит человек от двери:
```
Ресепшн
Коридор
Опенспейс
Переговорная
Кухня-лаунж
```
Смена зоны — мягкое перекрёстное растворение, без сдвигов.
Начинаем всегда с ресепшна.

Переходы — не лента, а план. Кнопки внизу по центру: круг со стрелкой,
повёрнутой по азимуту зоны на чертеже. Имя появляется подписью над кругом
по наведению и по фокусу, а для скринридера стоит именем кнопки всегда.
Стрелка возврата — туда, откуда только что пришли, — тише прямых.

Связи двусторонние: куда можно уйти, оттуда можно и вернуться.

```
Ресепшн        → Коридор, Опенспейс
Коридор        → Ресепшн, Кухня-лаунж, Опенспейс, Переговорная
Кухня-лаунж    → Коридор, Опенспейс
Опенспейс      → Ресепшн, Коридор, Кухня-лаунж, Переговорная
Переговорная   → Коридор, Опенспейс
```

Углы стрелок берутся не из этого списка, а из плана: в компоненте лежат
центроиды зон, снятые с чертежа, азимут считается на месте. Поменяется
чертёж — поменяются координаты, а не набор захардкоженных чисел.

**Где направление честно не работает.** Опенспейс тянется вдоль всей южной
кромки, поэтому из него всё остальное лежит «на севере»: ресепшн и кухня
расходятся на 1°, коридор и переговорная — на 10°. Из переговорной коридор
и опенспейс расходятся на 9°. Стрелки там показывают правду, но правда
неразличима на глаз — различают подпись и имя кнопки.

**Текст рядом с кадром.** Аргументы, которые закрывают сделку, живут
здесь и меняются вместе с зоной. Блок чередует сторону, чтобы не закрывать
главное в кадре. Плашки под текстом нет: он лежит прямо на кадре, а контраст
держит градиентная вуаль от кромки — см. design-system.md, раздел «Вуаль».
Название зоны — самое крупное на экране после самого кадра.

```
Ресепшн       Свет, материалы, форма —
              всё готово принимать гостей
Коридор       Просторное помещение
Опенспейс     26 рабочих мест
Переговорная  На 6–8 человек
Кухня-лаунж   Барная группа на пять мест, техника установлена
```

**Точек в конце нет ни у одной строки.** Сняты 1 сентября 2026 по просьбе
заказчика — вместе с точкой у обязательной строки под блоком. Это подписи
к кадру, а не проза: точка в конце одиночной строки поверх фотографии
читается как сор и мешает правому набору в Коридоре и Переговорной, где
она висит за общей кромкой. Появится вторая фраза внутри строки — точка
между предложениями остаётся, снят только хвост.

Сокращено заказчиком 1 сентября 2026 года. Ушли вторые строки —
«Проект и согласования сделаны», «Мебель входит в аренду, докупать
нечего», «Срок до въезда: день обращения, а не месяцы»: те же аргументы
разворачиваются ниже, в экономике и вопросах, а на кадре они мешали
смотреть кадр. У коридора описания нет вовсе — работает сам кадр,
отбивку до «Открыть планировку» держит заголовок (`.zoneNameBare`).
Перенос строки у ресепшна ручной (`\n` в тексте, `white-space: pre-line`):
фраза делится по смыслу, а не по ширине колонки.

Единственное красное — цифра `0` и полоса растра под ней.

**Обязательная строка внизу.** Не удалять:
```
Визуализация по дизайн-проекту. Помещение готово — приезжайте и сверьте
с оригиналом.
```

**Целевая кнопка в углу — убрана.** «Записаться на просмотр» живёт
только в самом низу сайта, в форме контакта; в офисе её больше нет.

**Выхода назад к башне нет.** Кнопка «К башне» и глобальный `Esc`
удалены вместе со скролл-секвенцией: hero-видео позади не существует,
возврат к нему — только перезагрузкой страницы. Уход вниз по прокрутке
зону не трогает: вернулся наверх — та же комната.

**Планировка**
```
Открыть планировку
```
Открывает чертёж поверх всего. Закрывается по Esc и по клику вне листа.
Площади отдельных зон на чертеже не подписываем: по нему они не обмерены,
а выдумывать нельзя. Количество мест и людей — считано по чертежу.
Векторная трасса с интерактивными зонами придёт позже.

проверит аналитик и на чём потеряет доверие ко всей странице.

```
Оксана Арензон
Управляющая объектом

+7 909 379-80-15
Написать в Max
kryakushina@arenda-34.ru
```

**Дополнительно, тихой строкой** — фактическая раскладка ряда ссылок
под телефоном:
```
kryakushina@arenda-34.ru   Написать в Max   Чертёж   3D-модель
```

«Скачать презентацию» отсюда ушло 1 сентября 2026: PDF в проекте нет,
а вместо него зритель получает то же самое живьём — «Чертёж» открывает
обмерный лист, «3D-модель» — кукольный дом, оба те же самые, что
в офисе. Esc возвращает к форме. Клик по зоне в модели уводит в офис,
в эту зону.

«Написать в Max» рисуется, только когда в `lib/contacts.ts` лежит
личная ссылка профиля `max.ru/u/…`: ссылки по номеру телефона
у мессенджера не существует.

Три поля вместо двух стоят живых денег: по данным Unbounce, одно поле
даёт 13,4 % конверсии, три — 10,1 %, пять — 7,8 %. Больше двух не ставим
ни при каких обстоятельствах.

## Состояния формы

**Отправляется**
```
Отправляем…
```

**Успех**
```
Готово. Оксана перезвонит на +7 909 ___-__-__.
Если удобнее написать — её мессенджер выше.
```

**Ошибка сети**
```
Не отправилось. Попробуйте ещё раз или позвоните
напрямую: +7 909 379-80-15.
```

**Пустое имя**
```
Как к вам обращаться?
```

**Некорректный телефон**
```
Проверьте номер — кажется, не хватает цифр.
```

Ошибки не обвиняют пользователя и всегда дают обходной путь.
