# office-flow.md — занавесы и шов

> Про `components/OfficeStop.tsx` и `components/OfficeStop.module.css`.
> Хвост секции башни под занавес — в `SEQUENCE.md` и `lib/sequence.ts`.
> Кукольный дом — `docs/interior.md`. Параллакс кадров зон — `docs/parallax.md`.
> Зона в офисе и её сброс — `components/OfficeHub.tsx`, коротко ниже
> в разделе «Зона: без памяти между визитами».

**v3: доводки больше нет.** Оба занавеса были чистой функцией прогресса
скролла и до v3, но поверх них стояла автодоводка — `lib/snap.ts`, таймер
90 мс и `window.scrollTo`, который силой доводил занавес до 0 % или 100 %,
если человек останавливался дальше 20 % хода границы. Богдан толкнул
предыдущую версию в `main` без проверки на localhost и попросил убрать
и это, и память зоны между визитами (ниже) — оставить чистый скролл.
Файл `lib/snap.ts` удалён целиком, вместе с эффектом в `OfficeStop.tsx`,
который на него подписывался. Отдыхать на середине занавеса теперь —
законное состояние покоя, а не брак: секвенция башни отдыхает на середине
скраба точно так же, и это никого не смущает.

## Механика, одна на оба перехода

Референс — quadplex80.com, разобран покадрово с шагом 1/12 с. Что там
происходит, дословно:

- приходящий экран выезжает снизу и накрывает уходящий;
- **уходящий не двигается**: ни масштаба, ни прозрачности, ни параллакса,
  ни размытия — он стоит, и его накрывают;
- стык — жёсткая горизонтальная линия. Ни градиента, ни перекрёстного
  растворения, ни мягкой кромки;
- всё движение занимает около 500 мс.

На сайте это реализовано дважды:

| | Что едет | Переменная |
|---|---|---|
| Занавес 1 | вся сцена офиса над башней | `--c`, 0 → 1 |
| Занавес 2 | слой кадра вида над офисом | `--p`, 0,06 → 0,34 |

Если однажды захочется «смягчить переход» — это будет уже другой переход,
а не улучшение этого.

### Чего больше нет

Засветка стекла (`.glass` в `TowerSequence`) удалена вместе с ведущим её
кодом. Белая вспышка и занавес — две метафоры одного момента, и вместе
они читались как брак. То же самое с фазовой картой v1: там кадр вида
поднимался, офис одновременно уезжал на 0,98 и гасил интерфейс. Три
метафоры на один переход. Осталась одна.

## Геометрия: как офис оказывается над башней

```
башня   0 ────────────── скраб 300svh ──────────── занавес 80svh ──┐
                                                                   │
офис            margin-top: -180svh   ┌── занавес 80svh ── фазы 220svh ──┐
                                      ↑
                            начинается ровно там, где кончается скраб
```

Секция башни стала выше на `CURTAIN_SVH = 80svh`. Кадры по этому хвосту
уже не идут: индекс упирается в последний и стоит. `travelSvh` не тронут,
дистанция скраба считается как `высота обёртки − 100svh − занавес`.

**Отступ −180svh, а не −80svh, и это арифметика, а не вкус.** Чтобы башня
во время занавеса не двигалась, сцена офиса должна быть УЖЕ пришпилена
к верху экрана в момент, когда занавес начинается. Пришпиливается она,
когда верх её обёртки доходит до верха экрана, — значит обёртка обязана
начинаться ровно там, где кончается скраб. Отсюда
`−(100svh + занавес) = −180svh`, и это число не зависит от `travelSvh`:
на всех трёх брейкпоинтах оно одно.

Замер на 1440×900 (`svh` = 900):

| | Документные координаты |
|---|---|
| обёртка башни | 0 … 4320 (480svh) |
| скраб башни | 0 … 2700 (300svh) |
| занавес 1 | 2700 … 3420 |
| башня пришпилена до | 3420 |
| обёртка офиса | 2700 … 6300 (400svh) |
| офис пришпилен | 2700 … 5400 |
| фазовая карта | 3420 … 5400 (220svh) |

Башня отпускает липкость ровно в конце занавеса. Проверено: на
2700 / 2880 / 3060 / 3240 / 3420 её липкий блок стоит на `top: 0`
без единого пикселя смещения, а сцена офиса идёт 900 → 675 → 450 → 225 → 0.

`transform` на сцене занавеса — причина, по которой кукольный дом теперь
уезжает порталом в `body`: любой трансформированный предок, хоть
`translateY(0)`, становится содержащим блоком для `position: fixed`,
и план поехал бы вместе со сценой да ещё и обрезался её `overflow`.

## Фазовая карта `--p`

```
0,00–0,06   мёртвая зона, офис интерактивен

0,06–0,34   ЗАНАВЕС 2. Кадр вида: translateY 100 % → 0 %.
            Слой офиса — статика: ни масштаба, ни прозрачности.
            Интерфейс горит и уходит под кромку.
            С 0,09 офис получает pointer-events: none и inert.

0,34–0,52   выдержка. Подпись проявляется за 0,35–0,44,
            translateY 12 px → 0.

0,52–1,00   шов: полоса 0 → 34svh, кадр 1,06 → 1,00,
            подпись уходит за 0,52–0,78.
```

Огибающие собираются в CSS:

```css
--rise:    clamp(0, (var(--p) - 0.06) / 0.28, 1);
--cap-in:  clamp(0, (var(--p) - 0.35) / 0.09, 1);
--cap-out: clamp(0, (var(--p) - 0.52) / 0.26, 1);
--seam:    clamp(0, (var(--p) - 0.52) / 0.48, 1);
```

`--c: 0` и `--p: 0` объявлены на сцене по умолчанию и это не косметика:
без них до первого кадра привода `var(--p)` невалиден и все `calc`
отваливаются целиком.

**Движутся ровно три вещи: `transform`, `opacity` и высота полосы шва.**
Ни `filter`, ни `blur`, ни `backdrop-filter`, ни маски на самом кадре.

## Подпись на кадре вида

Кегли сошли на ступень вниз **по той же шкале**, своих не изобретали:

| | Было | Стало |
|---|---|---|
| Заголовок | `--display-l`, 50 px | `--heading`, 23 px |
| Абзац | `--lead`, 21 px | `--small`, 15 px |
| Надзаголовок | `--label` | `--label` |
| Ширина блока | 40rem | 20rem |

Блок на 1440×900 — **320 × 211 px** против прежних 640 × 238.
По площади это 44 %, не треть: узкий блок того же текста становится выше,
и площадь падает медленнее ширины. Меньше уже нельзя — текст верстается
дословно из `copy.md`, а кегли ниже ступени в шкале нет.

### Вуаль

Приём тот же служебный, что в офисе: градиент `--paper` от кромки кадра
в прозрачность, только альфа, без единой резкой границы.
`design-system.md`, раздел «Вуаль».

Теперь это псевдоэлемент самой подписи, а не слой в процентах экрана:
размер у него содержательный. Обнимает блок с запасом 32 px, к левой
и нижней кромкам кадра доходит вплотную, а растворяется на 160 px
по горизонтали и 140 по вертикали.

**Хвост длинный нарочно.** С коротким (64 px) вуаль читалась не вуалью,
а белой плашкой с почти отвесной правой гранью — ровно тем, что
`design-system.md` запрещает. С длинным профиль яркости по горизонтали
идёт непрерывно: 236 → 227 → 201 → 183 → 165 → 150 → 127 → 111 → 94,
без ступени.

Площадь — 576 × 464 = 267 тыс. px² против 1094 × 648 = 709 тыс. в v1.
**38 % прежней.**

### Контраст, замер по реальным пикселям кадра

Заголовок сошёл с `--display-l` на `--heading` и перестал быть крупным
текстом: раньше ему хватало 3:1, теперь нужно 4,5:1, как абзацу.
Компенсировали глубиной, а не площадью — альфа 0,97 против 0,96, и,
главное, сплошная альфа по всему тексту: в v1 текст выходил на
растворяющуюся часть маски, там и был провал до 4,20:1.

Замер по глифовым пикселям, `p = 0,48`:

| Элемент | 1440 | 390 |
|---|---|---|
| Надзаголовок «23 ЭТАЖ», `--ink` | **15,53:1** | 15,53:1 |
| Заголовок `--heading`, `--ink` | **15,54:1** | 15,51:1 |
| Абзац `--small`, `--ink` | **15,46:1** | 15,40:1 |
| «Вид из окон помещения», `--ink-60` | **5,48:1** | 5,49:1 |

Порядок замера: два скриншота одного кадра — с текстом и с текстом,
перекрашенным в `transparent`, — разность даёт маску глифов, яркость
берётся из второго по этой маске.

## Шов

Не тронут. Полоса прижата к нижней кромке сцены, поверх кадра, ровно два
слоя-псевдоэлемента без собственной подложки:

```css
.band::before { background: var(--frit-dense);
                mask-image: linear-gradient(to top, #000 0%, #000 30%, transparent 100%); }
.band::after  { background: var(--frit-sparse);
                mask-image: linear-gradient(to top, #000 0%, transparent 100%); }
```

На ≤ 828 px обе плотности становятся `--frit-mid`, полоса — не выше 22svh.

**Полоса шва — единственный источник CLS на странице.** Она единственный
сдвигающийся элемент, и сдвигается только её собственная коробка — ни
одна строка текста и ни один кадр от неё не едут. Убрать сдвиг можно
было бы, зафиксировав высоту полосы и анимируя вместо неё геометрию
маски, но тогда растровая сетка перестала бы ползти вместе с кромкой,
то есть шов стал бы выглядеть иначе. Шов трогать не велено — число
CLS, которое он даёт, см. «Замеры».

## Зона: без памяти между визитами

`OfficeHub` не размонтируется никогда — компонент живёт всё время, пока
жива страница, — но памяти между визитами у него больше нет ни у зоны,
ни у кадров.

**В DOM в любой момент лежит кадр ровно одной зоны**, текущей. Раньше
в стопке накапливались все посещённые: пять полноэкранных WebP/AVIF
одновременно, если человек обошёл всё помещение. Возврат в уже
посещённую зону теперь грузит её кадр заново — так же, как первый визит.
`ZoneParallax` от этого не пострадал: он и раньше искал `<img
data-zone="…">` по значению текущей зоны, а не по индексу в стопке,
и карта глубины перезаливается в текстуру при каждой смене — проверено
поштучным вызовом `run()` в измерении ниже, кадры разных зон дают разные
`data-zone` на единственном смонтированном `<img>`.

**Зона сбрасывается на ресепшн при любом уходе из офиса, а не только
по «К башне».** Раньше уход вниз по скроллу и обратно возвращал туда,
где человек был; теперь — нет, ровно как просил Богдан. Механика —
не таймер и не отдельный слушатель, а тот же приём, что уже
стоял в файле для закрытия плана: правка состояния `zoneId` прямо
в теле рендера, на смене пропа `active` с true на false. `active` —
это `phase === 'office'` в `OfficeStop`, то есть «занавес его не
накрывает прямо сейчас»: уход в любую сторону, вверх к башне или вниз
к виду из окна, гасит `active` и вместе с ним зону. Тот же кадр,
которым «К башне» и раньше сбрасывала `zoneId` синхронно с кликом,
до начала своего проезда, — здесь никакого проезда нет, но принцип
тот же: сброс происходит сразу, не дожидаясь, пока занавес долистает.

## Просьба убрать движение

`prefers-reduced-motion: reduce` — равноправная ветка, не запасной
вариант. Обёртка схлопывается в `height: auto`, отрицательный отступ
обнуляется (секция снова встаёт после башни), сцена перестаёт быть
липкой и трансформированной, офис и кадр становятся двумя обычными
секциями по `100svh`, полоса шва сразу стоит финальными 48 px в потоке.
Все строки, все числа и оба экрана на месте.

## Замеры

Переизмерено после удаления `lib/snap.ts`: сам привод (`--c`/`--p` из
`getBoundingClientRect`) не менялся ни строкой, поэтому числа почти
совпадают с версией с доводкой — она никогда не стояла в горячем пути
кадра, только в отдельном слушателе поверх. Прогон каждого участка
за 3 с, экран 121 Гц (бюджет кадра 8,3 мс):

| | 1440, без троттлинга | 390, CPU ×4 |
|---|---|---|
| **Занавес 1** среднее / p95 / макс | 8,33 / 9,2 / 9,4 мс | 8,33 / 9,2 / 9,4 мс |
| дольше 16,7 мс | 0 из 356 | 0 из 356 |
| **Занавес 2** среднее / p95 / макс | 8,33 / 8,9 / 9,3 мс | 8,33 / 9,2 / 9,4 мс |
| дольше 16,7 мс | 0 из 356 | 0 из 356 |
| **Шов** среднее / p95 / макс | 8,33 / 9,0 / 9,6 мс | 8,33 / 9,2 / 9,4 мс |
| дольше 16,7 мс | 0 из 356 | 0 из 355 |

Троттлинг процессора занавесы почти не трогает: вся работа на композиторе,
главный поток пишет две строки в `style`.

**Клемпинг проверен на границах, не только серединой хода.** `--c`
и `--p` читаются как computed style ровно на 0,00 и 1,00 на обоих
концах каждого занавеса и за их пределами — при `scrollY`, для которого
формула дала бы отрицательное число или число больше единицы, `clamp01`
режет его тем же приёмом, что индекс кадра в `lib/sequence.ts`. Отдельно
проверено отсутствие автодоводки: остановка на 21 % занавеса 1 (выше
бывшего порога 20 %) держится сколько угодно, `window.scrollTo` за это
время вызывается ровно ноль раз — патчен и залогирован на всю сессию.

**CLS — 0,04**, измерено трейсом Chrome DevTools (windowed-метрика,
а не сумма всех `layout-shift` записей за сессию — прямое суммирование
на этом же прогоне даёт 0,15, потому что не группирует записи в окна).
Единственный виновник по-прежнему полоса шва; код `.band` в v3 не
менялся ни строкой, доводка на CLS не влияла — она двигала `scrollY`,
а не геометрию, — поэтому расхождение с более ранним замером в 0,01
это разница методики измерения, а не регрессия.

Первый экран после сборки — **178,3 КБ gzip**, восемь чанков,
`WebGLRenderer` ни в одном. Было 179,1 КБ до этой работы: `lib/snap.ts`
из бандла ушёл, портал плана остался.
