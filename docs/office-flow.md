# office-flow.md — офис, вид из окна и шов между ними

> Про `components/OfficeStop.tsx` и `components/OfficeStop.module.css`.
> Hero-видео — раздел «Hero-видео» в `AGENTS.md`. Кукольный дом —
> `docs/interior.md`. Параллакс кадров зон — `docs/parallax.md`.

---

## Что изменилось и почему

Раньше офис был оверлеем. `ActOne` фиксировал `body` через
`position: fixed` с отрицательным `top`, и пока офис открыт, страница
не листалась вообще. Выйти можно было ровно одним способом — кнопкой
«К башне». Для страницы, которую открывают на переговорах и пересылают
финдиру, это тупик: человек листает вниз, ничего не происходит, и он
считает, что сайт кончился.

Теперь первый экран — hero-видео полёта к башне (`HeroVideo` внутри
`HeroGate`), а после него страница идёт обычной прокруткой:

```
HeroVideo   постер облаков → «Войти» → ролик полёта → выезд ресепшна
#office     OfficeStop      офис-остановка + кадр вида из окна + шов
#landing    Landing         ряд чисел, абзац, кнопки (над ним StickyBar)
```

`ActOne.tsx` удалён. Скролл заблокирован ровно на время жизни hero
(`HeroGate`); в финале ролика секция офиса выезжает снизу, hero
размонтируется, и дальше блокировок нет. Возврат к hero — только
перезагрузка страницы.

## Устройство OfficeStop

Одна высокая секция: `calc(100svh + 220svh)`. Внутри — липкая сцена
на `100svh` с `overflow: hidden` и двумя слоями:

| Слой | z-index | Что это |
|---|---|---|
| A | 1 | `OfficeHub` — офис, пять зон, стрелки между ними |
| B | 2 | кадр вида из окна, вуаль и подпись |
| — | 3 | полоса шва, прижата к нижней кромке сцены |

Приём: высокая секция плюс нативный `position: sticky`. Ни пиннинга,
ни ScrollTrigger. Причина — на свежих iOS адресная строка дёргает
закреплённые секции.

**Один слушатель скролла, дросселированный через rAF.** Он считает
прогресс `p` от 0 до 1 одним вычитанием из `getBoundingClientRect`
и пишет его в единственную CSS-переменную `--p` на узле сцены.
`IntersectionObserver` включает и выключает слушателя: пока секции нет
на экране, нет ни слушателя, ни кадров rAF. Ре-рендеров React на кадрах
не происходит вообще.

**Грубое состояние `phase`** (`office | photo | seam`) меняется только
на пересечении порогов, с мёртвой зоной ±0,005, и существует ровно для
одного — для `inert` на слое офиса.

## Фазовая карта

Пороги — доли прогресса секции, не пикселей. Меняешь высоту обёртки —
карта не ломается, но проверить надо.

```
p 0,00–0,08   мёртвая зона. Офис полностью интерактивен.

p 0,08–0,45   кадр поднимается: translateY 100 % → 0 %.
              Офис сжимается 1 → 0,98,
              его интерфейс гаснет 1 → 0 за 0,08–0,30.
              С p > 0,12 офис не ловит указатель и получает inert.

p 0,45–0,62   выдержка. Подпись проявляется за 0,46–0,55,
              translateY 12 px → 0.

p 0,62–1,00   шов: полоса 0 → 34svh, кадр 1,06 → 1,00,
              подпись гаснет 1 → 0 и уходит на −40 px за 0,62–0,85.
```

Всё это считается **в CSS**, из `--p`, пятью огибающими:

```css
--rise:    clamp(0, (var(--p) - 0.08) / 0.37, 1);   /* 0,08–0,45 */
--ui-out:  clamp(0, (var(--p) - 0.08) / 0.22, 1);   /* 0,08–0,30 */
--cap-in:  clamp(0, (var(--p) - 0.46) / 0.09, 1);   /* 0,46–0,55 */
--cap-out: clamp(0, (var(--p) - 0.62) / 0.23, 1);   /* 0,62–0,85 */
--seam:    clamp(0, (var(--p) - 0.62) / 0.38, 1);   /* 0,62–1,00 */
```

`--p: 0` объявлено на сцене по умолчанию и это не косметика: без него
до первого кадра привода `var(--p)` невалиден и все `calc` отваливаются
целиком.

**Движутся ровно три вещи: `transform`, `opacity` и высота полосы шва.**
Ни `filter`, ни `blur`, ни `backdrop-filter`, ни маски на самом кадре.
Маска поверх полноэкранной картинки перерисовывает весь кадр на каждом
тике. Маски есть только у полосы — она низкая и стоит на месте.

## Что здесь уже ломалось

**Масштаб кадра стоял на слое, а не на кадре.** Пока `scale(1.06)`
висел на том же узле, что и подъём, вместе с кадром растягивалась
подпись: набор шёл на 6 % крупнее заданного, а на шве ещё и
пересчитывался обратно — текст перерисовывался на каждом тике.
Хуже другое следствие: масштаб считается от центра, поэтому при
`translateY(100%)` верхняя кромка увеличенного слоя поднималась на 3 %
высоты — 27 px при экране 900 — и кадр выглядывал снизу в мёртвой зоне.
Теперь слой только поднимается, `scale` живёт на самом `<picture>`,
а разгон подрезает `overflow` слоя.

**Transform на корне офиса ставить нельзя.** Внутри `OfficeHub` лежит
кукольный дом в `position: fixed`, и любой трансформированный предок —
хоть `scale(1)`, это не `none` — становится для него содержащим блоком.
Поэтому масштаб офиса идёт не обёрткой, а двумя переменными внутрь:

```
--office-ui     1 → 0     прозрачность интерфейса и вуалей OfficeHub
--office-scale  1 → 0,98  масштаб стопки кадров зон
```

Обе читаются в `OfficeHub.module.css` с запасным значением 1, поэтому
офис остаётся рабочим и сам по себе.

## Шов

Полоса прижата к нижней кромке сцены, поверх кадра. **Ровно два слоя**,
оба — псевдоэлементы, оба без собственной подложки:

```css
.band::before { background: var(--frit-dense);
                mask-image: linear-gradient(to top, #000 0%, #000 30%, transparent 100%); }
.band::after  { background: var(--frit-sparse);
                mask-image: linear-gradient(to top, #000 0%, transparent 100%); }
```

Точки густо у нижней кромки, кверху редеют, между ними видно кадр.
Когда липкость отпускает, снизу выходит `Landing` со стандартной
полосой стыка секций — 48 px, `--frit-sparse`, `design-system.md` §3.
Она и сменяет шов.

На ≤ 828 px обе плотности становятся `--frit-mid`, а полоса —
не выше 22svh: мелкий растр на плотных экранах муарит. 828 —
граница «телефон», а не размер кадра.

## Память зоны

Зона живёт в состоянии `OfficeHub`, а он не размонтируется никогда:
уход вниз по скроллу и возврат наверх приводят ровно в ту зону,
из которой ушли. Проверено — уход в опенспейс, прокрутка до Landing,
возврат: опенспейс на месте.

**Сброса на ресепшн больше нет нигде.** Кнопка «К башне» и глобальный
`Esc` удалены вместе со скролл-секвенцией: уходить из офиса некуда,
hero-видео позади не существует (возврат — только перезагрузкой).
Обход начинается от двери один раз — при первом входе. Esc на ресепшне
и в зонах не делает ничего; единственный Esc живёт внутри
`PlanDollhouse` и закрывает только планировку.

## Кадр вида

Файлы: `public/view/view-{640,1280,1920,2560}.{webp,avif}` плюс
`manifest.json`. Собираются `scripts/view-images.mjs` — тем же путём,
что рендеры зон. Ширины продублированы в `OfficeStop.tsx`, чтобы
строить `srcset` без ожидания сети; пересобираешь — сверь с манифестом.

`<picture>` монтируется, когда секция ближе полутора экранов
(`IntersectionObserver`, `rootMargin: 150% 0px`), с `fetchPriority="low"`
и `decoding="async"`. С уходом скролл-секвенции секция офиса стоит
сразу за hero (100svh), поэтому порог срабатывает уже при `scrollY = 0`:
кадр едет фоном с загрузки страницы, пока зритель смотрит постер, —
осознанно, через десять секунд ролика он реально нужен. Низкий
приоритет не даёт ему толкаться с preload видео.

**Кадр сейчас — заглушка.** Скриншот стороннего панорамного
просмотрщика, а не съёмка из помещения 113Н. Что менять, когда приедет
настоящая, — списком в шапке `OfficeStop.tsx`, блок `ЗАГЛУШКИ — ЗАМЕНИТЬ`.
Обрезка в рецепте скрипта снимает интерфейс просмотрщика и буквы
румбов «СЗ»/«С»: стороны света в `docs/facts.md` помечены как гипотеза,
и на сайте их нет ни строкой, ни пикселем.

## Контраст подписи

Тот же приём, что в офисе: не плашка, а вуаль — градиент `--paper`
от кромки кадра в прозрачность, маска режет его по горизонтали.
Вертикальный профиль альфы взят у `.scrimInfoLeft` из
`OfficeHub.module.css` буква в букву.

**Шире, чем в офисе, и это замер, а не вкус.** В офисе вуаль 62 %
с маской, сплошной до 48 %, и этого хватает: рендеры зон светлые.
Здесь под текстом городская панорама с тёмной развязкой, и по реальным
пикселям кадра худший контраст выходил **4,20:1** — на конце строки
«и в кабинет», x ≈ 681 px при экране 1440, там, где маска уже почти
растворилась. Строка абзаца доходит до 704 px, то есть до 49 % ширины,
поэтому вуаль расширена до 76 %, а маска держится сплошной до 53 %.

Замер после правки, по глифовым пикселям на кадре:

| | Контраст |
|---|---|
| `--ink` (надзаголовок, заголовок, абзац) | **14,09:1** |
| `--ink-60` (подпись «Вид из окон помещения») | **5,24:1** |

Альфу углублять не понадобилось, хватило ширины.
`design-system.md`, раздел «Вуаль», условие 4.

## Просьба убрать движение

`prefers-reduced-motion: reduce` — не запасной вариант, а равноправная
ветка. Обёртка схлопывается в `height: auto`, сцена перестаёт быть
липкой, офис и кадр становятся двумя обычными секциями по `100svh`,
полоса шва сразу стоит финальными 48 px в потоке, скролл не управляет
ничем. Все строки, все числа и оба экрана остаются на месте.

Проверено подменой `conditionText` медиазапроса в CSSOM: высота
обёртки 1848 = 900 + 900 + 48, `position: static` у сцены,
`transform: none` у кадра, подпись на полной прозрачности.

| | 1440, без троттлинга | 390, CPU ×4 |
|---|---|---|
| Кадров за прогон | 360 | 358 |
| Среднее время кадра | 8,29 мс | 8,33 мс |
| p95 | 9,0 мс | 9,2 мс |
| Максимум | 9,5 мс | 9,4 мс |
| Кадров дольше 16,7 мс | **0** | **0** |

Экран замера — 121 Гц, то есть бюджет кадра 8,3 мс, и шов в него
укладывается целиком. Троттлинг процессора шов не трогает: вся работа
на композиторе, главный поток пишет одну строку в `style`.

`CLS: 0.00` за всю прокрутку от офиса до Landing — трейс Chrome DevTools.

Первый экран после сборки — **177,8 КБ gzip**, восемь чанков,
`WebGLRenderer` ни в одном. Было 176 КБ до этой работы.
